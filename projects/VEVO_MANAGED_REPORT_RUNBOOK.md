## Candidate, promotion and recovery

Promotion pauses only VEVO reporting and drains every generation for a continuous 120 seconds. Protected configuration and role-policy snapshots are reread at mutation boundaries and at most once per minute while polling. An observed active managed deployment, capture or provider-reading task blocks dispatch. Later natural task overlap is recorded; this is not a global provider read lock and their schedules are preserved.

The candidate keeps the production input prefix. A separate scoped role can read VEVO report inputs and its own probe prefix, and write only its own markers/artifacts. It cannot write live aliases, journals, release pointers, SES or CloudWatch metrics. The application additionally blocks financial/email/native mutation paths, requires query-only GraphQL, disables both financial runners/email, and replaces only the upload sink. All full/7/30/90-day HTML/payload artifacts and quality evidence must be complete and privately hash-verified. Live output metadata must remain unchanged. A successful exact-page read retry/fallback may resolve its error; another page cannot hide it. Open empty continuation, duplicated inventory, exhausted reads or a safety cap blocks promotion. A proven requested-date boundary need not scan older history.

Only the identified candidate receives a managed hash-bound signal after task/IP/service/path and localhost proof. The complete promotion contract is validated before enabling; source/build/image are checked again after the final drain. Actual final runtime, immutable receipt, CAS pointer and released lease generation are verified. Existing historical GrowthBook source/quality receipts remain unchanged.

Known-state failures pause/drain and restore the original VEVO schedule and previous successful pointer; rollback creates separate immutable audit history. Foreign schedule/pointer changes are never overwritten. Uncertain task launch, role ownership, pointer or terminal release retains an incident lease and pauses a still-owned VEVO target. No uncertain lease is stolen, cleared or silently reacquired. Only the exact owned diagnostic task/role is cleaned up; natural or foreign tasks are not stopped. The workflow's 360-minute bound includes probe, drains and cleanup headroom.

IAM role creation is attempted once. Exact tagged ARN/trust is reconciled across a bounded 60-second visibility window, including a temporarily missing cleanup read. An unresolved create never becomes “absent/clean” from one `NoSuchEntity`; it retains an incident. This accounts for [documented IAM propagation delays](https://docs.aws.amazon.com/IAM/latest/UserGuide/troubleshoot.html#troubleshoot_general_eventual-consistency), not an observed live failure of this implementation.
