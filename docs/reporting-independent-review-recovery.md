# Recovering an interrupted independent reporting review

The committed normal-release controller owns runtime changes. An independent
publisher supplies a narrowly bound review; it must not restart that controller,
replace the release ID, or claim that probe approval verifies a later LIVE run.
Use the current `PROJECT_STATE.md` and actual AWS journal, rather than a historic
local command, to identify the active release.

## Establish the boundary before recovery

Confirm the exact source commit, immutable image, release ID, service, task ARN,
Fargate instance identity, private IP, and `/app` path. Require the actual host and
localhost markers before provider execution. Check the current controller's full
process identity, owned lease, paused schedule, stopped probe, absent temporary
role, all protected schedules/definitions/outputs, and both dashboard boundaries.
An active controller with a legitimate renewing lease must not be duplicated or
terminated. A missing ECS description is not positive authorization evidence.

Retain the failed invocation, actual OS exit code, log, input hashes, and every
raw runtime read before making another attempt. Classify whether failure occurred
before either write, after the private financial proof, or after the controller
review. A local traceback alone does not establish cloud write state: reconcile
the exact keys with owner-bound, encrypted full GETs and the current journal.

## Paths and publication order

Pass absolute, plain, repository-scoped paths for every evidence argument. Use
fresh, unique directories for the two runtime guards and preserve old directories.
A publisher must fail on relative or aliased paths before SDK access. Advertising
review inputs must also remain within their explicitly authorized local scope;
an exact-byte copy can resolve an admission path mismatch without changing data.

The private financial proof and final controller review are separate objects.
Each first publication uses conditional creation, AES256, expected bucket owner,
and full byte-exact readback. If the proof exists but the review does not, recovery
may reuse only the exact verified proof by GET. It must not repeat the proof PUT,
overwrite it, or treat an existing object as equivalent without comparing bytes.
If the final review already exists, reconcile controller progress instead of
publishing another review or blindly rerunning the failed local publisher.

## Required admission for a proof-only partial publication

Require a recent actual read-only recovery inspection bound to the failed
invocation and exact existing proof. Replay the original financial sixteen checks,
geographic JSON/HTML checks, native/credit/source provenance and complete private
checkpoint. Preserve all original monetary functions, tolerances and source
budgets. Run two fresh current-owned runtime guards around archive/proof reads,
compare the protected boundary, verify source/input bytes remain unchanged, and
check final guard freshness before one conditional final-review PUT. Save the
actual authorization receipt and both guards for the completed archive.

Meta responses used by the probe and LIVE are distinct source snapshots. Capture
and independently reconstruct each phase's actual responses, native EUR values,
query/cursor identities, complete marker and Git source files. A later API fetch
cannot prove the original cent allocation. Do not relax source equality merely
because a fresh response differs slightly, infer source values from report QA,
or substitute probe source evidence for LIVE source evidence.

## Completion

Authorization alone is not completion. Require the actual successful LIVE task,
new immutable generation, original LIVE financial checks, full financial CSV row
comparison, actual JSON/HTML display checks, enabled future dynamic-date schedule,
protected peer project, then authenticated HTTP and a separate honest browser
observation. Keep browser failure explicit; HTTP success does not imply a browser
test. Archive all source/recovery/publication/terminal evidence privately and
verify exact owned finite processes ended with no listeners. Never kill processes
by runtime name or by an unverified numeric PID. Update and push project state;
keep source main fixed while the active controller still binds it.
